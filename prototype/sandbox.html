What is real here, and what is not

Every tile launches the same FEG-provided game package, served unmodified from a separate origin under its own URL namespace (/g1, /g2, …), so each has separate browser cache entries — warming one never warms another. That is what keeps the hit-rate story honest rather than a demo trick.

Poster art is generated from that package's own splash background and symbol atlases; no PSK or third-party artwork is used. Titles, providers and chips are the ones listed publicly on the production lobby, reproduced as labels only. Layout, colours and tile geometry are matched to the production stylesheet.

What "load" means here, precisely. Click to the game frame's load event, with the blocking authorization check inside it. That is the furthest a lobby can honestly measure: the parent cannot see inside a cross-origin game frame, so it observes that one event and nothing more.

And what it does not mean. For this package the engine keeps streaming assets well past its own load event — measured from outside the page, the cold path is quiet at about 4.8 s, not 0.6 s. So treat the figure above as a floor on the baseline, not a full account of it. The pre-initialised path has no such gap: its frame finished loading during browse, which is why it reports single-digit milliseconds and issues no further requests. tools/sandbox_measure.mjs measures both from outside.

Not playable. None of these is click-to-playable. This sandbox has no provider backend, so no input-accepted signal exists and none is claimed. Launch-to-play conversion needs that backend and is reported as UNKNOWN rather than approximated with something that merely sounds similar.
